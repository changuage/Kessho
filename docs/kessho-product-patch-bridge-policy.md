# Kessho Product Patch Bridge Policy

## Scope

Exact Pad, Lead, and Drum parameter arrays are no longer accepted as Product source state. The retained snapshot ABI slots are zero-only reserved fields kept for binary layout stability until the Product snapshot ABI can take a breaking revision.

This policy covers every exact patch count and array field currently present in the snapshot ABI and module adapter patches. `SourceState` no longer stores exact Pad/Lead/Drum fields. Generated generic source preset rows in both TypeScript and C++ no longer expose exact Pad/Lead/Drum fields; the remaining generated source-preset module params live in family-specific Product Core tables until the shared modules accept structured preset and override inputs directly. The web-authored `ProductSourceSnapshot` type no longer exposes exact Pad/Lead/Drum fields; the web encoder writes zeroes for retained ABI exact slots and rejects legacy exact source fields if they are present at runtime.

Compatibility exact snapshot arrays must be empty: count must be zero and every retained value slot must be finite zero. Partial exact patch counts, wrong-family exact payloads, oversized counts, nonzero values, and non-finite exact values are invalid state, not fallback inputs to be completed, ignored, clamped, copied, or zero-filled at runtime.
Sparse override payloads are valid only for their source family, only when every counted index/value is valid. Web snapshot encoding must reject legacy exact source fields and invalid sparse override counts, indices, and values instead of clamping or ignoring them. C++ snapshot loading must reject invalid sparse override counts, indices, values, and exact ABI payloads instead of clamping or ignoring them.

Generated source preset IDs and Drum voice preset IDs are strict canonical inputs. Unknown IDs are rejected at snapshot/live-event boundaries; Product Core must not substitute a default preset or copy the sibling morph endpoint as a fallback.
The web snapshot adapter follows the same rule for explicit preset keys: missing UI state may select a documented default, but unknown non-empty source or Drum voice preset keys serialize as invalid IDs so Product Core rejects the snapshot instead of masking the state behind defaults or exact arrays. Web Pad and Lead snapshots do not emit exact arrays for invalid endpoint IDs. Custom Lead preset data is anchored to valid generated endpoint IDs and encoded through bounded sparse Lead overrides; if an endpoint without custom data has an explicit unknown key, Product Core rejects the invalid ID. Web Drum snapshots do not emit exact or sparse Drum patch payloads for invalid voice preset IDs.

## Classification Values

- `CANONICAL_CORE_FIELD`: final Product Core-owned state, safe to keep as architecture.
- `TEMP_COMPAT_WEB_REFERENCE`: generated or adapter state copied from the web reference to preserve parity while Product Core reconstruction catches up.
- `DEPRECATED_BRIDGE_FIELD`: host-authored exact patch state that must be retired and must not become the musical owner.
- `RESERVED_ABI_FIELD`: retained ABI layout slot that must stay zero-only and must not be used as musical state.

## Source Reconstruction Proof

- Drum voice preset bridge: `cpp/KesshoCore/src/product/sources/DrumSource.cpp` reconstructs a Drum voice patch from `preset_id`, `drum_voice_preset_a_ids`, `drum_voice_preset_b_ids`, and `drum_voice_morphs`.
- Web Drum reconstruction mirror: `src/audio/CoreProductDrumPatch.ts` uses generated Drum voice preset params plus generated snap-param indices to emit bounded sparse Drum overrides for generated-voice custom controls without exposing exact Drum snapshot fields. Invalid Drum voice preset IDs emit no sparse Drum override payload, leaving Product Core to reject the invalid IDs.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` proves the `Soft Touch` sub voice preset ID path renders the same audio as equivalent bounded sparse Drum overrides.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` proves generated-voice Drum sparse overrides load into structured `SourceState`, compile into the generated Drum source patch, update live through `SetSourceOverride`, and trigger without any SourceState exact Drum fields.
- Web Pad full-state default caches and selected endpoint caches are not considered user overrides when generated endpoint IDs and morphs can reconstruct the selected patch. The web bridge no longer scans every generated Pad preset looking for cache matches; generated-endpoint non-default Pad control edits now use bounded sparse Pad override fields, while invalid/non-reconstructable Pad endpoint IDs emit no exact fallback arrays and are rejected by Product Core.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` proves generated-endpoint Pad sparse overrides load into structured `SourceState`, update live through `SetSourceOverride`, and trigger without any SourceState exact Pad fields.
- Generated-endpoint non-default Lead preset data and custom Lead preset data now use bounded sparse Lead override fields, while invalid/non-reconstructable Lead endpoint IDs emit no exact fallback arrays.
- Generated TypeScript source preset rows and generic C++ `KESSHO_PRODUCT_SOURCE_PRESETS` rows no longer carry exact Pad/Lead/Drum arrays. Product Core compiles temporary module-boundary patches from family-specific generated `KESSHO_PRODUCT_PAD_SOURCE_PRESETS`, `KESSHO_PRODUCT_LEAD_SOURCE_PRESETS`, and `KESSHO_PRODUCT_DRUM_SOURCE_PRESETS` tables plus endpoint, morph, distance, and override state; web Pad and Lead endpoint reconstruction derives params from generated preset IDs plus structured preset/spec metadata, and Drum uses generated Drum voice preset param blocks.
- Shared Pad, Lead, and Drum modules now reject missing, partial, or non-finite module-boundary patch params instead of synthesizing profile-derived fallback params, keeping Product Core as the sole preset reconstruction owner.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` and `cpp/KesshoCore/tests/ProductLeadExactPatchTests.cpp` prove generated-endpoint Lead sparse overrides load into structured `SourceState`, apply after endpoint reconstruction, update live through `SetSourceOverride`, and trigger without any SourceState exact Lead fields.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` proves runtime generated Pad, Lead, and Drum `SetParam` events for reconstructable sources update bounded sparse override state and live module patches without SourceState exact fallback state.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` rejects partial exact Drum snapshots instead of completing them into full compatibility arrays.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` rejects wrong-family, oversized, overloaded Soundscape, nonzero, and non-finite exact bridge payloads instead of copying, clamping, clearing, or zero-filling them.
- `src/audio/coreProductSnapshotEncoder.ts` rejects legacy exact source fields plus invalid sparse override counts, indices, values, and wrong-family sparse payloads during snapshot byte encoding. `cpp/KesshoCore/src/product/KesshoProductSnapshot.cpp` rejects invalid sparse override counts, indices, values, wrong-family payloads, and any nonempty exact ABI payload during snapshot load.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` rejects unknown source preset IDs and Drum voice preset IDs in snapshots and live `SetSourcePreset` events instead of falling back to defaults or sibling endpoints.
- `sourcePresetPatch` requires a validated generated preset reference; Product Core call sites validate source-family ownership before patch compilation, and default engine state seeds explicit generated Drum voice preset IDs instead of relying on zero-ID lookup behavior.
- Product snapshot load rejects invalid Pad/Lead generated endpoint IDs and nonempty exact compatibility arrays, so exact arrays cannot hide a bad generated endpoint mapping.
- Soundscape route, texture, and module params now use dedicated Product snapshot fields and are loaded into Soundscape-owned `SourceState` fields; web snapshot serialization, render, asset, and graph code must not use overloaded exact Pad/Drum arrays for Soundscape state.

## Canonical Replacement Fields

The canonical path for source identity and musical ownership is:

- `preset_id` / `presetId`: `CANONICAL_CORE_FIELD`
- `morph`, `distance`, `expression`, `level`, sends, post-LPF, stereo width, and hold seconds: `CANONICAL_CORE_FIELD`
- Pad and Lead source preset endpoint IDs in `source_preset_a_id`, `source_preset_b_id` / `sourcePresetAId`, `sourcePresetBId`: `CANONICAL_CORE_FIELD`
- Pad source distance for generated Pad endpoint tonal shaping and bounded sparse Pad override fields in `pad_override_count`, `pad_override_indices`, `pad_override_values` / `padOverrideCount`, `padOverrideIndices`, `padOverrideValues`: `CANONICAL_CORE_FIELD`
- Lead envelope override state in `lead_envelope_override_enabled` / `leadEnvelopeOverrideEnabled` plus source attack/decay/sustain/release, Lead algorithm override state in `lead_algorithm_preset_a_enabled` / `leadAlgorithmPresetAEnabled`, source distance for generated Lead endpoint tonal shaping, and bounded sparse Lead override fields in `lead_override_count`, `lead_override_indices`, `lead_override_values` / `leadOverrideCount`, `leadOverrideIndices`, `leadOverrideValues`: `CANONICAL_CORE_FIELD`
- Drum voice endpoint IDs and morphs in `drum_voice_preset_a_ids`, `drum_voice_preset_b_ids`, `drum_voice_morphs` / `drumVoicePresetAIds`, `drumVoicePresetBIds`, `drumVoiceMorphs`: `CANONICAL_CORE_FIELD`
- Drum source level, source reverb send, and bounded sparse Drum override fields in `drum_override_count`, `drum_override_indices`, `drum_override_values` / `drumOverrideCount`, `drumOverrideIndices`, `drumOverrideValues` for generated Drum voice-preset patches: `CANONICAL_CORE_FIELD`
- Live sparse override edits use generated `SetSourceOverride` slot/commit events for Pad, Lead, and Drum. Runtime generated Pad, Lead, and Drum `SetParam` edits for reconstructable sources also normalize into the same sparse override state; the snapshot fields remain canonical saved-session state until the shared modules accept structured Product Core patch inputs directly.
- Snapshot byte encoding and Product Core snapshot loading are fail-closed for exact/sparse bridge fields: web-authored snapshots reject any legacy exact source fields, C++ rejects nonzero exact counts, nonzero exact values, and non-finite exact values, and both sides reject invalid sparse override counts, indices, values, and wrong-family sparse payloads rather than clamping, clearing, ignoring, or zero-filling them.
- Generated Product Core source preset macro fields: `CANONICAL_CORE_FIELD`

The snapshot adapter may map legacy preset keys into these generated fields. It may not be treated as the final owner of oscillator, filter, envelope, FM, or Drum tonal behavior.

Generated preset ID lookup is fail-closed: adapters may choose explicit defaults before snapshot creation, but Product Core must reject unknown IDs after the snapshot/event boundary.

## Enforcement

- `scripts/check-kessho-product-patch-bridges.mjs` fails if an exact patch field is not listed here with a classification and retirement condition, or if retired `SourceState.exact_*` fields reappear.
- Web snapshot exact patch builders must carry a `PATCH_BRIDGE_RETIREMENT` label.
- New exact patch fields are forbidden unless this document classifies them and the static check is updated in the same change.

# Kessho Product Patch Bridge Policy

## Scope

Exact Pad, Lead, and Drum parameter arrays are temporary parity bridges. They are allowed only while the Product Core finishes replacing legacy Web TS tonal interpretation with generated Product Core preset IDs, generated Product Core preset metadata, and bounded user override fields.

This policy covers every exact patch count and array field currently present in C++, TypeScript, generated schema, module adapter patches, and web snapshot encoding.

Compatibility exact patch arrays must be complete fixed-capacity patches on their owning source family, and every counted value must be finite. Partial exact patch counts, wrong-family exact payloads, oversized counts, and non-finite exact values are invalid state, not fallback inputs to be completed, ignored, clamped, or zero-filled at runtime.
Sparse override payloads are valid only for their source family, only when the matching exact compatibility array is empty, and only when every counted index/value is valid. Web snapshot encoding and C++ snapshot loading must reject invalid sparse override counts, indices, values, and mixed exact/sparse state instead of clamping or ignoring them.

Generated source preset IDs and Drum voice preset IDs are strict canonical inputs. Unknown IDs are rejected at snapshot/live-event boundaries; Product Core must not substitute a default preset or copy the sibling morph endpoint as a fallback.
The web snapshot adapter follows the same rule for explicit preset keys: missing UI state may select a documented default, but unknown non-empty source or Drum voice preset keys serialize as invalid IDs so Product Core rejects the snapshot instead of masking the state behind defaults or exact arrays. Web Pad snapshots do not emit exact arrays for invalid endpoint IDs. Web Lead snapshots do not emit exact arrays for invalid endpoint IDs unless explicit custom Lead preset data is present, which remains a classified compatibility path with generated endpoint IDs cleared. Web Drum snapshots do not emit exact or sparse Drum patch payloads for invalid voice preset IDs.

## Classification Values

- `CANONICAL_CORE_FIELD`: final Product Core-owned state, safe to keep as architecture.
- `TEMP_COMPAT_WEB_REFERENCE`: generated or adapter state copied from the web reference to preserve parity while Product Core reconstruction catches up.
- `DEPRECATED_BRIDGE_FIELD`: host-authored exact patch state that must be retired and must not become the musical owner.

## Source Reconstruction Proof

- Drum voice preset bridge: `cpp/KesshoCore/src/product/sources/DrumSource.cpp` reconstructs a Drum voice patch from `preset_id`, `drum_voice_preset_a_ids`, `drum_voice_preset_b_ids`, and `drum_voice_morphs` when `exact_drum_param_count` is zero.
- Web Drum reconstruction mirror: `src/audio/CoreProductDrumPatch.ts` uses generated Drum voice preset params plus generated snap-param indices to omit `exactDrumParams` for reconstructable snapshot states and emit bounded sparse Drum overrides for generated-voice custom controls. Invalid Drum voice preset IDs emit neither exact Drum arrays nor sparse Drum override payloads, leaving Product Core to reject the invalid IDs.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` proves the `Soft Touch` sub voice preset ID path renders the same audio as an equivalent exact `exact_drum_params[0..125]` snapshot patch.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` proves generated-voice Drum sparse overrides load into structured `SourceState`, compile into the generated Drum source patch, update live through `SetSourceOverride`, and trigger without promoting back to exact Drum patch state.
- Web Pad full-state default caches and selected endpoint caches are not considered user overrides when generated endpoint IDs and morphs can reconstruct the selected patch. The web bridge no longer scans every generated Pad preset looking for cache matches; generated-endpoint non-default Pad control edits now use bounded sparse Pad override fields, while invalid/non-reconstructable Pad endpoint IDs emit no exact fallback arrays and are rejected by Product Core.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` proves generated-endpoint Pad sparse overrides load into structured `SourceState`, update live through `SetSourceOverride`, and trigger without promoting back to exact Pad patch state.
- Generated-endpoint non-default Lead preset data now uses bounded sparse Lead override fields, while invalid/non-reconstructable Lead endpoint IDs emit no exact fallback arrays unless explicit custom Lead preset data is present.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` and `cpp/KesshoCore/tests/ProductLeadExactPatchTests.cpp` prove generated-endpoint Lead sparse overrides load into structured `SourceState`, apply after endpoint reconstruction, update live through `SetSourceOverride`, and trigger without promoting back to exact Lead patch state.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` proves runtime generated Pad, Lead, and Drum `SetParam` events for reconstructable sources update bounded sparse override state and live module patches without promoting the source back to exact patch state.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` rejects partial exact Pad, Lead, and Drum runtime fallback state and partial exact Drum snapshots instead of completing them into full compatibility arrays.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` rejects wrong-family, oversized, overloaded Soundscape, and non-finite exact bridge payloads instead of copying, clamping, clearing, or zero-filling them.
- `src/audio/coreProductSnapshotEncoder.ts` and `cpp/KesshoCore/src/product/KesshoProductSnapshot.cpp` reject invalid sparse override counts, indices, values, wrong-family payloads, and mixed exact/sparse state instead of clamping or ignoring those fields during snapshot byte encoding/load.
- `cpp/KesshoCore/tests/ProductSourceWrapperTests.cpp` rejects unknown source preset IDs and Drum voice preset IDs in snapshots and live `SetSourcePreset` events instead of falling back to defaults or sibling endpoints.
- `sourcePresetPatch` requires a validated generated preset reference; Product Core call sites validate source-family ownership before patch compilation, and default engine state seeds explicit generated Drum voice preset IDs instead of relying on zero-ID lookup behavior.

- Soundscape route, texture, and module params now use dedicated Product snapshot fields and are loaded into Soundscape-owned `SourceState` fields; web snapshot serialization, render, asset, and graph code must not use overloaded exact Pad/Drum arrays for Soundscape state.

## Canonical Replacement Fields

The canonical path for source identity and musical ownership is:

- `preset_id` / `presetId`: `CANONICAL_CORE_FIELD`
- `morph`, `distance`, `expression`, `level`, sends, post-LPF, stereo width, and hold seconds: `CANONICAL_CORE_FIELD`
- Pad and Lead source preset endpoint IDs in `source_preset_a_id`, `source_preset_b_id` / `sourcePresetAId`, `sourcePresetBId`: `CANONICAL_CORE_FIELD`
- Pad source distance for generated Pad endpoint tonal shaping and bounded sparse Pad override fields in `pad_override_count`, `pad_override_indices`, `pad_override_values` / `padOverrideCount`, `padOverrideIndices`, `padOverrideValues`: `CANONICAL_CORE_FIELD`
- Lead envelope override state in `lead_envelope_override_enabled` / `leadEnvelopeOverrideEnabled` plus source attack/decay/sustain/release, Lead algorithm override state in `lead_algorithm_preset_a_enabled` / `leadAlgorithmPresetAEnabled`, source distance for generated Lead endpoint tonal shaping, and bounded sparse Lead override fields in `lead_override_count`, `lead_override_indices`, `lead_override_values` / `leadOverrideCount`, `leadOverrideIndices`, `leadOverrideValues`: `CANONICAL_CORE_FIELD`
- Drum voice endpoint IDs and morphs in `drum_voice_preset_a_ids`, `drum_voice_preset_b_ids`, `drum_voice_morphs` / `drumVoicePresetAIds`, `drumVoicePresetBIds`, `drumVoiceMorphs`: `CANONICAL_CORE_FIELD`
- Drum source level, source reverb send, and bounded sparse Drum override fields in `drum_override_count`, `drum_override_indices`, `drum_override_values` / `drumOverrideCount`, `drumOverrideIndices`, `drumOverrideValues` for generated Drum voice-preset patches: `CANONICAL_CORE_FIELD`
- Live sparse override edits use generated `SetSourceOverride` slot/commit events for Pad, Lead, and Drum when exact compatibility arrays are empty. Runtime generated Pad, Lead, and Drum `SetParam` edits for reconstructable sources also normalize into the same sparse override state; the snapshot fields remain canonical saved-session state until the shared modules accept structured Product Core patch inputs directly.
- Snapshot byte encoding and Product Core snapshot loading are fail-closed for exact/sparse bridge fields: invalid exact counts, wrong-family exact arrays, non-finite exact values, invalid sparse override counts, indices, values, wrong-family sparse payloads, and mixed exact/sparse state are rejected rather than clamped, cleared, ignored, or zero-filled.
- Generated Product Core source preset profile fields: `CANONICAL_CORE_FIELD`

The snapshot adapter may map legacy preset keys into these generated fields. It may not be treated as the final owner of oscillator, filter, envelope, FM, or Drum tonal behavior.

Generated preset ID lookup is fail-closed: adapters may choose explicit defaults before snapshot creation, but Product Core must reject unknown IDs after the snapshot/event boundary.

## Enforcement

- `scripts/check-kessho-product-patch-bridges.mjs` fails if an exact patch field is not listed here with a classification and retirement condition.
- Web snapshot exact patch builders must carry a `PATCH_BRIDGE_RETIREMENT` label.
- New exact patch fields are forbidden unless this document classifies them and the static check is updated in the same change.

# Product Core Web Audio Graph Parity

This is the proof design for full `web-ts` versus `core-product` graph parity. Module parity is necessary but not sufficient: the migration is only complete when the same source signals feed the same buses, the same bus processors run in the same order, and the same master output is produced within declared tolerances.

## Success Criteria

- Every active domain in `docs/kessho-product-web-audio-graph-parity.manifest.json` has status `proven`. Deferred rewrite domains are excluded from active blocker counts until they explicitly re-enter the active parity plan.
- Web and Product Core expose matched capture boundaries for source dry outputs, source sends, FX inputs/outputs, dynamics input/output, master pre-limiter, and master post-limiter.
- Focused corpus cases compare those boundaries, not only the final master.
- Full-scene corpus cases compare aligned master output after boundary parity is established.
- `npm run core:product:web-graph-parity:strict` passes and is included in the Product Core CI path.

## Gate Semantics

The audit distinguishes active parity domains from intentionally deferred rewrite domains. Deferred domains may retain historical smoke/master cases, but failing deferred cases do not block the active parity audit or strict gate. They become blocking again only after the domain status is changed back to `blocked`, `partial`, or `proven`.

## Current Missing Parity

- Matched capture boundaries now exist for every named domain, and dynamics/sidechain/master, soundscape layers, Delay A/B, reverb macro/context shaping, and drum/source sends now have enough focused boundary comparisons plus full-scene master proof to be marked `proven`.
- Boundary smoke exists and a first master-output corpus exists, but strict parity is not proven for active domains: granular and diffuse/source spatial sends. Spectral freeze is deferred for a bottom-up rewrite and no longer counts as an active blocker.

## Test Shape

Each focused corpus case should render both runtimes from the same snapshot and compare:

- Source dry and pre-fader send buffers.
- FX input, direct output, and send taps.
- Dynamics input/output and sidechain gain traces.
- Master pre-limiter and post-limiter output.

Strict acceptance should use deterministic thresholds for C++/WASM module paths and explicitly looser thresholds only where the Web reference depends on browser-native nodes such as `DelayNode`, `BiquadFilterNode`, or `DynamicsCompressorNode`.

The retained tests should stay at matched bus boundaries plus a representative master corpus. The corpus should not absorb every exploratory probe: keep delayed-freeze granular boundary/master proof when it becomes active, keep deterministic reverb wash/bloom decay and one broader no-hook reverb scene, keep any new production failures as blockers unless the implementation has been aligned first, and loosen only known browser-native/sample-shape residuals. Legacy granular cloud and unresolved production mismatches should not be converted into green tests by broad tolerances.
